Detail hero

The head of a subscription's own screen: the merchant's mark, its name, its price and the word for how often. It answers "what is this and what does it cost me" in one glance, before anything else on the page has been read.

Molecule6 grey pagesone form, no axisno stateshosts 2 atoms

Anatomy

Four content slots, two of them atoms this component hosts and does not restyle. Everything below is drawn by design/system/components/detail-hero.css through the same entry point a product screen loads, so this page cannot drift from the screens.

Spotify Premium

$11.99 a month
  • .hero the molecule: a flex row with a 16px gap, aligned to the top rather than to a baseline, and one 8px margin under it
  • .logo an atom, the Logo, at its largest size in the product: 52px with the container corner. The size belongs to the atom's own size-by-container axis and is declared in logo.css, not here
  • h1 the merchant name, 20px. The only slot this file styles directly besides the cycle word
  • .amt an atom, the Amount, at 32px weight 700, which is its largest size and the closest anything in this product gets to the monthly total. Declared in amount.css
  • .cycle "a month". This molecule's own slot, muted, sitting inline after the figure. It is not a Muted line: it has no margin and it is not a paragraph
  • align-items flex-start and deliberately not baseline: a 52px square baseline-aligned to a 20px heading hangs below the block and drags the two lines under it with it

It positions its atoms and repaints neither. The only rule this file writes about the logo is flex: none, which is layout, and the atom already declares it: the rule is carried unchanged from kit.css rather than deleted, because deleting a declaration is a named decision and this file makes none. It is a backlog line so the deletion happens once, out loud, with the markup.

Variants and sizes

One form, and this is the one component in the round that genuinely has no axis. All six states of the subscription detail put the same four slots in the same order at the same sizes. What varies is what the slots contain, and content is not an axis: a real mark or a drawn question mark, a merchant name or the raw statement string, a price or a skeleton. Drawing a matrix of that would be drawing a matrix of the product's data.

The three forms below are the same component, three times, to show that claim rather than assert it. Read them as evidence, not as variants.

Netflix

$17.99 a month

A named merchant. The mark is the person's own Netflix, in full brand colour: it is data rather than chrome, which is why it is the only saturated object on the screen and why it is contained in a square instead of being masked to the interface colour.

SQ *BLUEBOTTLE 8890

$14.00 seen monthly

The unmatched charge, node 2.7. The name slot holds the raw statement string because that is all we have, and the square holds a drawn question mark rather than a mark. It is quiet and not clay: an unnamed charge is an ordinary gap in the data, not a failure, so it takes the recessed square and the muted tier. The empty square and its drawn mark belong to the Logo atom, which selects that form structurally because the grey has no class to hook.

There is no loading form, and its absence is the most interesting thing about this component. On the loading state every other block on the screen is skeletonised, the facts, the code wash and the charge list, and the hero renders complete, with the real mark, the real name and the real price. The grey original says why in its own comment: the list the person tapped already knew the name and the amount, and blanking out what they had a moment ago is the thing that state must not do. So this molecule has three content forms and not four, and the fourth is absent by decision rather than by omission.

No size axis, and no emphasis axis. The hero is one size because there is one of it per screen and it is always the subject of that screen. A hero at a second size would be a hero that is not the subject, which is a different screen.

When to use it

Once, at the top of a subscription's own screen, and nowhere else. It is the object that closes the loop the guided reveal opened: a person recognised the name in a chip group, tapped the row on Home, and this is where the thing they tapped identifies itself with a mark, a name and a price.

The order of the slots is the order of the questions. What is it (the mark, then the name). What does it cost (the figure). How often (the word). "a month" is written as a word beside the number and never as a slash and an abbreviation, which is the plain money language principle in one detail: $11.99 a month, never $11.99/mo.

The name is 20px and not the 24px a page subject takes elsewhere in the product, and that is deliberate: the loudest thing on this screen is the price under it, and a name set at page-subject size would compete with the number a person came to check.

The rule, and the anti-rule

The mark keeps its square

Disney+

$13.99 a month

52 by 52, a container corner, and the mark filling it edge to edge with alt="". The name beside it is the accessible name; a screen reader reads one subscription and not two fragments. The square never shrinks when the name is long, which is what flex: none is for.

Never let the mark set the row
A 52px logo baseline-aligned to a 20px heading, hanging below the block

The row is aligned to the top of its content, not to a text baseline. Baseline alignment lets the tallest child decide where everything sits, and here the tallest child is a picture: the name and the price would drift down the screen by however tall the square happened to be. This is layout the molecule owns, and it is the reason the molecule exists at all rather than being three elements in a row.

Use a hero for the subject of a screen

One subscription, identifying itself at the top of its own page. The figure is 32px because on this screen it is the number the page is about.

Use a subscription row in a list
Disney+in 11 days · Aug 12$13.99

The same three facts inside a list are the subscription row, .row: a 36px mark, a 15px name, a 14px figure at the far end, and the whole row is one link with one accessible name. The tell is whether the person is scanning or has arrived. A hero inside a list would give every item a 32px price and turn a calm list into a column of shouting numbers.

States

None, and it was checked rather than assumed. The hero is a readout: it holds no anchor and no button on any of the 6 grey pages or the 6 coloured ones, and it is not itself a target. Its logo is explicitly not one either, and logo.css says so and says why: on a list screen the whole row is the link, and on this screen the actions are in an action row further down. The three forms in the matrix above are content, and none of them is reachable by an interaction.

Three values moved and none was re-decided. The gap was 14px and is 16, the block margin was 6px and is 8, the name was 21px and is 20. Nearest step, ties to the larger, straight from the founder's review of the foundations. The atoms inside are untouched: the square is still 52px with the 14px corner and the figure is still 32px, both measured on the real subscription detail screen before and after.

One duplicate declaration was dropped and nothing moves. kit.css wrote .app .hero .amt { display: block } twice, 214 lines apart, and the first of the two also carries the atom's size. The size half went to amount.css with the rest of that atom's size axis; the bare repeat is not carried here, because a rule whose whole content is a property another file already sets at the same specificity is a second edition of that file.
